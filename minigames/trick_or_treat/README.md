# 🎃 不给糖就捣蛋（万圣夜寻糖）

每人报名时把 1 颗糖藏在 7 个部位之一，整场活动共 3 次搜查机会。搜查结果会公开播报，搜过的部位全员排除。第一个猜中的人拿走那颗糖。找到别人，或者自己的糖被找到，都算配对成功，一个人可以配对多次。

可以用皮套或任何自定义角色参加。报名表除了必选的藏糖部位，还有一个可选的【万圣节昵称】（最多 20 字，本轮内不能重名）。播报、公共进度、奖品记录和最终结果都优先显示昵称，没填才显示 @某人（只显示，不 ping）。`/trickortreat search` 的 target 从候选列表里选，列表显示昵称，没填昵称的显示服务器名字；也可以手动输入完整昵称。

部位（存的是稳定 ID）：嘴巴里 `mouth`、胸口 `chest`、腋下 `armpit`、耳后 `behind_ear`、内裤里 `underwear`、屁股缝 `butt_crack`、袜子里 `sock`。

## 指令

玩家：`/trickortreat join | search | status | board | prizes | withdraw`。入口面板上的三个按钮（报名藏糖 / 我的状态 / 公共进度）是持久按钮，重启后仍然有效。

管理（需要「管理服务器」权限，回调里会再校验一次）：`/trickortreat_admin`

| 子命令 | 作用 |
|---|---|
| `setup entry_channel announce_channel` | 设置报名入口和公告频道（可以是同一个），下一轮 open 时生效 |
| `config allow_late_join` | 开局后是否允许补报，默认允许 |
| `open` | 开新一轮（报名阶段），在入口频道发报名面板 |
| `panel` | 重发本轮报名面板 |
| `start` | 进入搜查阶段 |
| `close` | 结束本轮（会先二次确认），公布最终结果 |
| `status` | 查看运行状态、人数、待发和失败的公告 |
| `repair-announcements` | 把发送失败的播报重新排队并立即补发 |
| `restore user` | 恢复一位已退出的玩家（次数和藏糖位置都不重置） |

报名可以在入口频道或它的子区里进行。搜查只能在入口频道、公告频道和它们的子区里用。状态、进度和奖品可以在服务器任何地方查看，结果只有自己看得到。

## 部署与权限

- 没有新依赖。`bot.py` 的 `EXTENSIONS` 里已经加了 `minigames.trick_or_treat`，重启后 Slash 指令会全局同步。
- 玉猫在入口频道需要「发送消息、嵌入链接」权限。在公告频道还需要「读取消息历史」：补发播报前要核对这条有没有发过。
- 建议把入口和公告频道放在已经限制成年成员访问的区域。

## 数据

- 每个 Guild 一个 JSON 文件，放在 `data/trick_or_treat/<guild_id>.json`（`config.json` 的 `data_dir`），第一次写入时自动创建，不需要迁移。
- 写盘方式和皮套、RP 一样：Guild 锁内改副本，fsync 后原子替换。事务里任何一步校验失败，整笔都会丢弃，所以被拒绝的搜查不会扣次数。文件损坏时停止读写，不会覆盖原文件。
- 每轮活动都有独立的 `event_id`（e1、e2…），旧轮次只读保留。
- **回滚**：从 `EXTENSIONS` 里删掉这一行再重启即可。数据文件可以留着，也可以删掉。

## 公开播报（outbox）

- 搜查结果和最终结果，跟扣次数、记录搜查写在同一笔事务里，作为待发公告入队。事务提交后才会发送。
- 发送失败时不会回滚搜查。后台每 60 秒按入队顺序补发一次，遇到失败就停，避免线索顺序颠倒。超过 `outbox_max_retries` 次后标记为失败，需要管理员用 `repair-announcements` 重新排队。
- 每条播报的 footer 里带公告编号（`公告 #o12`）。如果上次「已经发出但没来得及记录」就崩溃了，补发前会在频道最近 50 条消息里找同一编号的玉猫消息，找到就直接记为已发，不再重复发送。这只能降低重复的概率，不能保证恰好发一次。如果仍然出现重复播报，删掉多余那条即可，游戏事实不受影响。
- 同一个交互重复送达时（按 `interaction_id` 识别），只回放第一次的结果，不会重复扣次数。

## 隐私

没被找到的藏糖位置只会出现在玩家本人的 `/trickortreat status` 里。公共进度、奖品记录、播报、最终结果和审计日志都不包含它。审计日志只记操作元数据。
